The `server` workspace runs the Express API for market data, CoverFi AI, health checks, legal/privacy support, and optional support records. Username ownership, protection creation, and username payment resolution are contract/client flows, not Firestore authority.

## Security controls

Current controls:

- JSON body size limit of `32kb`.
- Structured request logs with request IDs.
- Route-specific rate limits.
- Schema validation for wallets, receipts, legal records, account/support records, and AI prompts.
- Wallet-signed challenge/session authentication for private wallet resources.
- Optional Firebase-backed support records for receipts, chat history, legal acceptance, and privacy export/delete workflows.
- Wallet-scoped privacy export/delete endpoints for server-side data.
- Local CORS support for the main app, preview app, and protocol monitor.

Production should use a stable `AUTH_SESSION_SECRET`, shared session revocation storage, and distributed rate limits. Local development may use the process-local fallback secret, but it invalidates sessions on restart.

## Private route authentication

Private routes require:

```txt
X-CoverFi-Wallet-Address: <stellar-public-key>
Authorization: Bearer <signed-session-token>
```

Clients obtain a token with:

- `POST /api/auth/challenge`
- Wallet signs the returned challenge message.
- `POST /api/auth/session`
- `POST /api/legal/accept` records server-side terms acceptance for the signed wallet.

Routes that enforce the header include:

- `POST /api/receipts/save`
- `POST /api/legal/accept`
- `GET /api/privacy/export/:walletAddress`
- `DELETE /api/privacy/:walletAddress`
- `GET /api/ai/chat/:walletAddress`
- `POST /api/ai/chat` when a wallet address is supplied

## Firestore collections

| Collection | Purpose |
| --- | --- |
| `users` | Legacy username/session data. The Soroban username registry is the current authority. |
| `accounts` | Legacy profile/app data. The app now uses wallet-local browser state for profile and position display data. |
| `payments` | Legacy payment history. The app now stores wallet-local receipt history after signed payments. |
| `receipts` | Optional structured receipt records for support/manual receipt saves |
| `chats` | Wallet-scoped AI chat history |
| `legal_acceptances` | Wallet-scoped terms acceptance records |

## Required Firestore indexes

Create these composite indexes:

| Collection | Fields | Query |
| --- | --- | --- |
| `chats` | `walletAddress` ascending, `createdAt` ascending | Optional optimization for chat history |

The current chat route sorts in memory after a wallet filter. Add the chat index before raising history limits.

## Health checks

`GET /api/health` returns:

- `ok`
- `aiConfigured`
- `receiptStorage`
- `termsVersion`

Deployment platforms should use this route as the production readiness probe.

## Protocol monitor

The `coverfi-monitor` workspace is a read-only Vite app for local operations. It reads:

- `GET /api/health`
- `GET /api/legal/status`
- `GET /api/prices`
- `GET /api/portfolio/markets`
- Soroban contract getters for engine config, reserve balances, oracle timestamp, premium totals, and restricted payout policy.

Default local URL:

```txt
http://localhost:5175
```

## Environment variables

Keep these server-side only:

- `FIREBASE_SERVICE_ACCOUNT_BASE64`
- `DEEPSEEK_API_KEY`

Frontend-safe values:

- `VITE_API_BASE_URL`
- `VITE_FIREBASE_*`
- Stellar public contract IDs and public asset issuer IDs

## Deployment checklist

1. Set Firebase service account and project ID only if support records, chat history, or legal acceptance sync are enabled.
2. Enable Firestore Native mode for those optional records.
3. Create required Firestore indexes.
4. Confirm contract username resolution works through the Soroban registry.
5. Set frontend app URL and API base URL.
6. Run `npm run check`, `npm test`, and frontend builds.
7. Verify `/api/health` after deployment.
8. Verify the monitor can read contract and backend state.
